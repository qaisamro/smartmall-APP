## مهمة عاجلة: إصلاح اتجاه RTL/LTR للتطبيق بالكامل

المشكلة الحالية:

عند اختيار اللغة العربية، يتم تغيير النصوص والترجمات إلى العربية، لكن **اتجاه واجهة التطبيق بالكامل يبقى مثل English / LTR**.

أريد إصلاح المشكلة على مستوى **البنية المركزية للتطبيق**، وليس إضافة حلول يدوية لكل شاشة.

### الهدف النهائي

عند اختيار:

* العربية → التطبيق بالكامل RTL
* English → التطبيق بالكامل LTR

ويجب أن يشمل ذلك:

* Root Layout
* Header
* Bottom Navigation
* Tabs
* Sidebars / Drawers
* Cards
* Forms
* Inputs
* Buttons
* Icons/arrows ذات العلاقة بالاتجاه
* Lists
* Product screens
* Mall screens
* Search
* Cart
* Checkout
* Orders
* Notifications
* Profile
* Login/Register
* Scanner
* Offers

---

# 1. افحص أولًا قبل تعديل أي شيء

لا تبدأ بالتعديل مباشرة.

افحص هذه الملفات والأجزاء:

* `src/i18n/index.ts`
* `app/_layout.tsx`
* جميع ملفات language switching
* `I18nManager`
* `isRTL`
* `writingDirection`
* `direction`
* أي `useLanguage` أو language context
* Expo Router root layout
* `(customer)` layout
* `(tabs)` layout
* Bottom Tab Navigator
* أي RTL utility موجود حاليًا

حدد بالضبط:

1. أين يتم تحديد اللغة الحالية؟
2. أين يتم تحميل اللغة عند startup؟
3. هل اللغة العربية يتم تحميلها قبل إنشاء الـ root UI؟
4. هل `I18nManager` يتم ضبطه عند startup؟
5. هل `I18nManager.forceRTL()` أو `allowRTL()` مستخدمة؟
6. ماذا يحدث عند تغيير اللغة أثناء تشغيل التطبيق؟
7. هل التطبيق يحتاج Reload لكي يتغير الاتجاه؟
8. هل يوجد أكثر من مكان يتحكم بالاتجاه؟

لا تغيّر أي API أو backend.

---

# 2. إصلاح مركزي حقيقي

أريد أن يكون هناك مصدر واحد للحقيقة:

```text
Arabic  => RTL
English => LTR
```

يجب مزامنة اللغة الحالية مع React Native `I18nManager`.

المطلوب تقريبًا:

```text
currentLanguage
      ↓
isArabic
      ↓
I18nManager direction
      ↓
Root Layout
      ↓
Entire App
```

لا أريد حلولًا منفصلة لكل شاشة.

---

# 3. Startup / Initial Language

عند تشغيل التطبيق لأول مرة:

إذا كانت اللغة المحفوظة Arabic:

```text
language = ar
I18nManager = RTL
```

إذا كانت اللغة المحفوظة English:

```text
language = en
I18nManager = LTR
```

يجب تنفيذ ذلك **قبل أن يظهر التطبيق في الاتجاه الخاطئ قدر الإمكان**.

إذا كان React Native يتطلب Reload لتطبيق تغيير `I18nManager`، تعامل مع ذلك بطريقة صحيحة وآمنة.

لا تستخدم حلولًا تؤدي إلى loop أو إعادة تشغيل التطبيق بشكل مستمر.

---

# 4. Language Switching

عند تغيير:

English → Arabic

يجب أن يصبح التطبيق:

```text
Arabic
RTL
```

وعند:

Arabic → English

يجب أن يصبح:

```text
English
LTR
```

إذا كان تغيير `I18nManager` يتطلب Reload، استخدم آلية مناسبة للتطبيق الحالي.

المهم أن المستخدم بعد تغيير اللغة يرى التطبيق كاملًا بالاتجاه الصحيح.

---

# 5. Root Layout

يجب أن يكون الـ Root Layout هو المسؤول عن الاتجاه العام.

استخدم approach مركزي مثل:

```text
I18nManager
+
root direction
```

ولا تعتمد على تعديل كل شاشة منفردة.

يمكن استخدام:

```tsx
direction: isRTL ? 'rtl' : 'ltr'
```

على الـ root container إذا كان ذلك مناسبًا، لكن لا تستخدمه كبديل عن إصلاح `I18nManager`.

---

# 6. ممنوع هذا النوع من الحلول

لا أريد:

```tsx
flexDirection: 'row-reverse'
```

في عشرات الملفات.

ولا أريد:

```tsx
isRTL ? 'row-reverse' : 'row'
```

في كل component.

ولا أريد نسخ نفس RTL logic داخل كل شاشة.

ولا أريد تغيير layouts الحالية إلا إذا كان هناك عنصر محدد يحتاج معالجة بعد إصلاح الاتجاه المركزي.

**RTL يجب أن يكون Native/App-level وليس مجموعة hacks.**

---

# 7. Bottom Navigation

راجع Bottom Navigation بشكل خاص.

في Arabic يجب أن يتعامل التطبيق مع الاتجاه RTL بشكل طبيعي.

في English يجب أن يبقى LTR.

لا تغيّر أسماء أو ترتيب التبويبات الوظيفي الحالي.

التبويبات الحالية:

```text
Home
Malls
Offers
Orders
Profile
```

لا تغيّر الـ business logic أو routes.

```text

```
