D. Recommended Search & Discovery architecture
1. Preserve the existing public API contract
Use the existing routes rather than introducing new endpoints:

Global products:
GET /search/global
Malls:
GET /malls
Mall details:
GET /malls/slug/{slug}
Mall sections:
GET /malls/{id}/sections
Mall products:
GET /malls/{id}/products
Product details:
GET /products/{id}
Do not use /search unless the product decision specifically requires its different response and shelf-location behavior.

2. Keep separate search modes
Recommended mobile search modes:

Global Discovery

Product results grouped by mall
Optional mall result section using GET /malls?search=...
Existing /search/global remains the product source
Mall Discovery

Search products within a selected mall
Category filter
Main section and child section filters
Paginated product results
Product Details

Existing product route remains the final navigation target
This avoids mixing the non-paginated mall collection response with the paginated product response.

3. Reuse React Query
Continue using:

staleTime: 60 seconds
gcTime: 5 minutes
retry: 1
refetchOnReconnect: true

Recommended query keys should include every active filter:

['global-search', query]
['mall-search', search, type]
['mall-products', mallId, search, categoryId, sectionId]
['mall-sections', mallId]

Keep AbortSignal propagation in every catalog/search API function.

4. Preserve debouncing and cancellation
The current mobile 500 ms debounce is adequate for the mobile experience.

Future work should avoid:

Calling global search for fewer than two characters.
Sending requests for each keystroke.
Ignoring the React Query signal.
Issuing the extra full malls request solely to localize a global result when it is not necessary.
5. Handle response limitations explicitly
Global search is capped at 30 products and has no pagination contract. The mobile UI should communicate that it is a discovery result, not a complete catalog listing.

For complete mall product browsing, continue using the paginated mall products endpoint.

6. Keep history and suggestions client-only unless a real API exists
No backend endpoint for:

Search history
Recent searches
Suggestions
Trending searches
was found.

Do not invent one. If history is later required, it should initially be treated as a client-side feature with an explicit storage decision.

7. Keep Home and Bottom Navigation unchanged
The existing Home search entry point is already functional.

Search should remain a pushed route and should not be added as a fifth or sixth Bottom Navigation tab unless that product decision changes.

F. Risks and production limitations
Production route drift

The repository route tree and the live Hostinger API may not always be synchronized.
The existing production endpoint should be checked before changing mobile behavior.
Global result limit

/search/global returns at most 30 products.
There is no pagination or cursor parameter.
Mall name localization

Global search returns one mall_name, sourced from the Arabic mall name first.
The mobile UI currently performs an additional malls request to find an English name.
A future implementation should avoid unnecessary requests or explicitly accept this localization limitation.
Website nearby filtering is incomplete

The website sends lat, lng, and radius.
MallController::index() currently ignores those values.
Mobile should not claim that the existing API supports distance-based mall search.
Website mall product search lacks debounce

The website Mall Profile search sends a request on each input change.
Mobile's existing 500 ms debounce is safer and should be preserved.
Section and category semantics differ

Mall sections use mall_section_id.
Legacy products may still be linked through section_id.
The existing group_by_section backend behavior should be preserved rather than replaced with client-only filtering.
Different pagination models

Global search: fixed 30-result response.
Mall products: Laravel pagination, 24 products per page.
Mall list: non-paginated collection.
Current mobile search screen loads all malls

useMalls() is called without a filter on Search screen load.
This is an avoidable network request if only the global response's mall name is needed.
No suggestions or history contract

Search history and suggestions cannot be implemented against the current API without adding a new product/backend contract.
Public endpoints with optional bearer tokens

Search and catalog routes are publicly accessible.
The clients still attach a bearer token when available.
Future code should preserve the current client behavior and should not make these routes require authentication.
