PHASE 5 — STEP 2:
Build the professional Customer Profile & Account experience.

IMPORTANT RULES:

* Work ONLY inside `artifacts/smartmall-mobile`.

Inspect:

1. The existing mobile authentication/user implementation.
2. The existing `/me` or current-user API implementation.
3. The existing website profile/account implementation.
4. Existing production Laravel routes related to the authenticated customer profile.
5. Existing logout behavior.
6. Existing language/theme/session architecture.

Before making changes, report:

* Exact existing API endpoint(s) available for customer profile.
* HTTP methods.
* Request/response shapes.
* Whether profile update is supported.
* Whether password change is supported.
* Exact logout behavior.
* Any production limitations.

DO NOT create or modify backend endpoints.

* Account status if the API exposes it.

7. LOGOUT

---

Use the existing authentication/logout architecture.

Logout must:

* Clear the authenticated session/token using the existing secure mechanism.
* Clear appropriate authenticated React Query/cache state.
* Return the user to the login screen.
* Never expose or log the token.
* Never store tokens in AsyncStorage.

Do NOT invent a logout API endpoint.

If the current app performs local logout without a server endpoint, preserve that behavior.

---

8. PROFILE UI QUALITY

---

Make the screen look like a professional production mobile application.

Requirements:

* Safe area.
* Proper spacing.
* Clear section hierarchy.
* Consistent cards/list rows.
* Appropriate icons.
* Proper touch targets.
* Loading skeleton or polished loading state.
* Error + retry.
* Empty/fallback states where appropriate.
* No excessive visual decoration.
* Responsive on small and large phones.

Do not redesign the rest of the application.

---

9. RTL / LTR

---

This is critical.

Arabic:

* true RTL.
* text aligned right.
* logical padding using `paddingStart` / `paddingEnd`.
* icons and arrows logically positioned.
* section rows follow RTL.
* no hardcoded left/right where avoidable.

English:

* true LTR.
* text aligned left.
* normal directional icons/arrows.

IMPORTANT:

* Do NOT use `row-reverse`.
* Avoid double inversion with I18nManager.
* Follow the same RTL architecture established during Phase 4.
