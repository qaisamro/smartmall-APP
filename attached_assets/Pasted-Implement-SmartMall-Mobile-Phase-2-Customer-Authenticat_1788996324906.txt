# 4. AUTHENTICATION

Implement a professional customer authentication flow.

## Login

Create:

`/mobile/app/(auth)/login.tsx`

Use:

* React Hook Form
* Zod validation
* reusable form components
* loading state
* server error state
* validation errors
* keyboard-safe layout
* Arabic and English translations

Login request:

POST `/login`

Expected authentication response contains:

* `user`
* `access_token`
* `token_type`

Store ONLY the access token securely using Expo SecureStore.

NEVER store the bearer token in:

* AsyncStorage
* persisted Zustand
* plain files
* URL parameters
* query strings

Keep authentication state separate from sensitive token persistence.

---

# 5. AUTH STORE

Use the existing Phase 1 auth architecture if available.

The auth state should support:

* user
* isAuthenticated
* isLoading
* initialize()
* login()
* logout()
* refreshUser()

On application startup:

1. Read the token from SecureStore.
2. If no token exists, show the authentication flow.
3. If a token exists, call GET `/me`.
4. If `/me` succeeds, restore the user session.
5. If `/me` returns 401, remove the invalid token and return to login.

Do NOT assume a stored token is valid.

---

# 6. CENTRAL 401 HANDLING

The centralized API client must handle HTTP 401 consistently.

When an authenticated request receives 401:

* clear the stored token
* clear authenticated user state
* navigate to the login flow
* avoid infinite redirect loops

Do not implement authentication logic separately inside every screen.
