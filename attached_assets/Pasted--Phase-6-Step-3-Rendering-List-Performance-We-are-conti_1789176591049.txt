# TARGET 1 — Offers

Inspect the Offers screen.

If it currently renders a potentially large collection using:

* ScrollView
* `.map()`
* nested rendering

convert the main collection to an appropriate virtualized list, preferably `FlatList`.

Requirements:

* preserve the current visual design
* preserve card layout
* preserve navigation
* preserve loading states
* preserve empty states
* preserve pull-to-refresh if present
* preserve existing React Query behavior
* preserve image behavior
* preserve RTL/LTR behavior
* do not change the API

Use appropriate list optimizations only where justified, such as:

* `keyExtractor`
* `initialNumToRender`
* `maxToRenderPerBatch`
* `windowSize`
* `removeClippedSubviews` only if safe
* stable `renderItem`
* stable callbacks where useful

Do NOT blindly add every optimization.

`app/(customer)/(tabs)/search.tsx`

Improve rendering performance for larger result sets.

Goals:

* avoid unnecessary nested `.map()` rendering where practical
* use a virtualized list for the main result collection where appropriate
* keep grouped-by-mall behavior
* preserve mall headers
* preserve product cards
* preserve search navigation
* preserve loading state
* preserve empty state
* preserve the existing 500ms debounce
* preserve AbortSignal behavior added in Step 2
* preserve current API endpoint
* do not add search history/suggestions/trending
* do not add pagination to the global search API

Important:

Do NOT redesign the search UI.

Only improve how the existing results are rendered.

If a single FlatList with section-like data is more appropriate, use that only if it can be implemented without changing the user-visible behavior.

Requirements:

* keep existing infinite pagination

* keep existing API endpoints
* keep existing Mall Details UI
* keep existing product card design
* preserve `expo-image`

# GENERAL RENDERING RULES

For all three targets:

* Prefer React Native virtualization for large lists.
* Keep components simple.
* Use `React.memo` only where it provides a real benefit.
* Keep `keyExtractor` stable.
* Avoid using array indexes as keys when a stable product/offer ID exists.
* Avoid recreating expensive data structures on every render.
* Do not introduce unnecessary global state.
* Do not change React Query defaults.
* Do not change cache configuration.
* Do not change networking behavior except what already exists from Step 2.
* Do not change business logic.

Most importantly:

### DO NOT TOUCH WORKING FUNCTIONALITY JUST TO OPTIMIZE IT.

If a proposed optimization creates significant architectural complexity, leave that area unchanged and report it.
